# Бриф на разработку сайта (React)

Интерактивный бриф для клиентов: 99 вопросов из `text.md` разбиты на 10 экранов с условной логикой.
Вместо документа на 25 шагов клиент видит только те вопросы, которые относятся к его проекту.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # прод-сборка в dist/
npm run smoke    # проверка генерации документов (Client Brief + Internal Spec) в консоль
```

Прод-сборка — статика в `dist/`, деплоится куда угодно (Vercel, Netlify, любой хостинг): загрузите содержимое папки.

## Публикация на GitHub Pages

Настройка пути не нужна: workflow при сборке сам подставляет имя репозитория в базу (`BASE_PATH`), поэтому сайт работает при любом названии репо.

1. **Создайте публичный репозиторий** на GitHub (для Pages на бесплатном тарифе репо должно быть публичным), например `site-brief`.
2. **Из папки проекта** выполните и вставьте свои значения:

   ```bash
   git init
   git add .
   git commit -m "Бриф на разработку сайта: React-приложение"
   git branch -M main
   git remote add origin https://github.com/klon008/site-brief.git
   git push -u origin main
   ```

3. **Включите Pages через Actions** (единственный ручной шаг в GitHub):
   *Settings → Pages → Build and deployment → Source: **GitHub Actions***.
4. Дождитесь зелёной галочки во вкладке **Actions** — сайт появится на
   `https://klon008.github.io/site-brief/`.
5. Админка: `https://klon008.github.io/site-brief/#/admin`.

Дальше каждый `git push` в `main` пересобирает и обновляет сайт автоматически (вкладка Actions → Deploy to GitHub Pages). Перезапустить деплой руками можно там же: Actions → workflow → Run workflow.

Примечания:
- если репозиторий назван иначе — адрес будет `https://klon008.github.io/<имя-репо>/`, в конфиге менять ничего не нужно;
- исходники публичны, в том числе секрет шифрования из `src/lib/crypto.ts` — это согласуется с уровнем «микро-защиты»: файл `.brief` читается только вашим приложением, но не защищён от того, кто готов разбирать код;
- ответы клиентов нигде не хранятся на сервере — сайт полностью клиентский.

## Как это работает

- **10 экранов** вместо 25 разделов: О компании → Задача сайта → Клиенты → Старый сайт → Дизайн и бренд → Структура и контент → Функционал → Техническая часть → Сроки и бюджет → Открытые вопросы.
- **Условная логика** (файл `src/data/questions.ts`, поле `showIf`):
  - экран «Старый сайт» появляется, только если в вопросе 11 выбран вариант с существующим сайтом;
  - блок «Интернет-магазин» (в. 53–59) — только если в в. 52 отмечен «Интернет-магазин»;
  - «Какая CRM» (в. 61) — только если в в. 60 отмечена CRM;
  - языковые версии (в. 65–66) — только если в в. 64 выбрано «Да»;
  - загрузка логотипа/брендбука — только если они есть.
- **Отметки уверенности** у каждого вопроса: `✓ Знаю / ≈ Не уверен / ? Не знаю / ✕ Не относится` — выбор «Не знаю» в вариантах тоже учитывается.
- **Черновик** автосохраняется в localStorage браузера — можно закрывать и продолжать позже.

## Цикл «клиент → вы»

1. Клиент заполняет бриф и жмёт **«Скачать файл с ответами»** — скачивается один зашифрованный файл `brief-ГГГГММДД-xxxx.brief`.
2. Клиент отправляет файл вам (Telegram, email — как угодно).
3. Вы открываете приложение по скрытому адресу **`#/admin`** (например `https://ваш-домен/#/admin`), перетаскиваете файл в зону загрузки — видите результат: статистику 🟢🟡🔴, переключение Client Brief / Internal Spec, выгрузку .md/JSON и печать в PDF.

### Про шифрование

Файл шифруется **AES-GCM** (WebCrypto) ключом из секрета в `src/lib/crypto.ts`. Это «микро-защита»: клиент и посторонние видят в файле бинарную кашу и не узнают ни ответов, ни названия компании (имя проекта — внутри зашифрованной части, в имени файла только дата). Секрет зашит в бандл, поэтому от реверс-инжиниринга приложения это не защищает — для угрозы «клиент скинул файл кому-то ещё» этого достаточно. Хотите сильнее — замените константу `SECRET` на свою (файлы старых версий после этого не откроются).

Просмотр в `#/admin` не сохраняет загруженные ответы в ваш черновик — он остаётся нетронутым.

## Два документа

1. **Client Brief** — ответы клиента по разделам (виден клиенту в превью и вам в админке).
2. **Internal Spec** — рабочая таблица: Область / Ответ клиента / Статус (🟢🟡🔴⚪) / Нужно сделать + сводка и список открытых вопросов. Внутренний документ — клиенту не показывается ни на экране, ни в файле.

Действия из колонки «Нужно сделать» задаются в `src/data/questions.ts` полем `action`.

Клиенту доступна только одна кнопка — скачать зашифрованный `.brief`-файл. Все выгрузки (.md, копирование, печать в PDF, JSON) — в `#/admin`.

## Структура

```
src/
  model.ts               типы (вопрос, ответ, статус)
  data/questions.ts      все 99 вопросов, варианты, условная логика, действия для спеки
  lib/logic.ts           видимость вопросов, статусы, статистика
  lib/crypto.ts          шифрование/расшифровка .brief-файлов (AES-GCM)
  lib/exporters.ts       генерация Client Brief / Internal Spec / JSON, скачивание
  components/            Welcome, Stepper, SectionPage, QuestionField, Results, AdminUpload
  App.tsx                состояние, автосохранение, валидация, навигация, #/admin
scripts/export-smoke.ts  смоук-тест генерации документов и шифрования
```
